# 中继拓扑与运行边界

2026-11-16，设计交付；不是已部署、已完成故障域验收或采购决定。实际候选/运行状态见 STATE。

## 客户端结构

继续由一个 iroh Endpoint 管理设备身份、Direct、iroh Relay 与 QUIC 迁移。Khor 的 peer relay/SSH 通过现有 Custom transport 接入同一连接；不再增加独立的心跳、NAT 协议或第二套应用请求重放。先检查允许的完整路径是否可用，再按 CONNECTION-POLICY 比较稳定质量。

一个可达设备只能证明第一腿。只有它到目标的第二腿也可达、双方信任且用户策略允许，peer relay 才是替代路径。移动电脑和手机会睡眠、换地址或离线，因此它们可用于恢复和加速，不能充当唯一的基础设施容灾承诺。已有唯一存活 middle 的真实两腿及缓存恢复证据见 SOLE-PEER-RELEASE、SOLE-PEER-CACHE 和 LIVE-MIDDLE-RETRY。

本轮不新增第二个 Endpoint/同时双家。两个 Endpoint 会带来身份、发布、连接复用和闲置成本的另一组所有权问题；现有机制仍有可验证的单 Endpoint 故障接管空间。若后续故障注入证明原生单家无法满足必要的恢复预算，再以同一身份/发现与成本合同评估，不能只因多一个连接看似更可靠而启用。

## 按故障域计算冗余

当前源码配置中的北京 HTTP 和北京 TLS 是同一机器的不同进程/端口，不能算两台容灾节点；香港是另一地域。源码与历史 NET 文档不证明这些入口今天仍运行或所有设备都能访问。历史校园网只能访问国内这一约束，必须在部署决定前重新测量。

| 故障 | 现有替代条件 | 设计要求 |
| --- | --- | --- |
| 单个 Relay TCP 流静默、进程重启 | 同机新连接、其他已允许 Relay 或可信 middle 可用 | 原 demand-check/重连与真实业务验证；HTTP 能应答不算业务恢复 |
| 北京整机或出口失效 | 两端能访问香港/其他允许 Relay，或完整 peer relay 可用 | 不能把北京第二 URL 当容灾；双端分别验证替代入口和实际业务 |
| 某端只能访问国内且唯一国内 Relay 整机失效 | 没有另一条允许的完整路径时，无算法能保证恢复 | 如要求覆盖此故障，需另一台独立国内故障域节点；部署/采购另行批准 |
| 登记服务失效、两端同时冷启动 | 本地可信地址/其他实际登记点能引导建联 | 热连接继续可用不等于冷发现通过；分别注入缓存有/无、旧/新地址 |
| 自家 Relay 不可达 | 仅能使用用户允许的集合和可信 middle | 不绕过 only-mine、暂停、信任或单跳限制 |

每个候选 Relay 保持独立 URL。不要把两个有状态 Relay 隐藏在同一轮询 DNS 名后，假定设备身份会自动跨机复制。登记、QAD 和数据转发分别列故障域：一个提供三项服务的机器仍是一个故障点。第二登记点须确实配置到客户端并证明冷发布/解析，而不是只启动另一台服务。

## 容量和运维

沿用 iroh-relay 与 khor relay 的现有连接、速率和总量指标，不另造中继协议。历史文档提到每客户端上行限速；运行参数必须现场读取后才能作为当前容量结论。CPU/链路利用率不高但文件稳定撞到配额时，先识别限速，避免误判为 Rust/拥塞控制问题。客户端优化不能突破运营端设置的上限。

容量评估分别记录 Relay NIC 双向字节、单客户端限额、连接数、发送队列、CPU/内存和丢弃/重连，配合两端真实交互延迟与完整文件率。先在现有允许节点做并发和拥塞测量，再选择线路/供应商/地域；现阶段没有支持具体新机规格、数量或费用的容量数据，不把猜测写成已定预算。

发布前的运维验收要实际关停一个隔离 Relay、阻断一端、保留 TCP 但停止转发、清空冷发现缓存，并核对自动恢复、请求期限、无写重放及最终资源回收。生产机器不承担破坏性注入。回滚保持旧地址兼容与认证，不用 DNS 替换制造身份分裂。凭据只用现有配置/日志脱敏机制，监控仅保存必要的总量。

## 尚未关闭的验收

F3 已证明原静默故障三场与健康延迟三场的窄合同；固定 IPv6-only、双方换址、NAT64 也已有各自证据。这些不替代北京整机/出口、独立登记冷启动、容量、半断/发送堵塞及候选 iPhone 的最终验证。REQUIREMENTS 的 N4.2–N4.5 继续保持未完成，不能由本设计文档直接改绿。

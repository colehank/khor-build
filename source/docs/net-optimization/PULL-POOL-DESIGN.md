# 并发文件的连接与额度候选设计

这是下一轮实现前的设计，尚未实现或验收，不代表参数最优。基于 eacc 的首内容和运输失败回退行为；该源306项标准已闭，准确版本和proof见STATE。继续保持默认 shared，候选仅用于内部 separate 实验；不修改 vendor 或安装 App。

## 所有权

Node 已有 ears: Mutex<Option<Arc<iroh::Endpoint>>>。通过持有 ears 锁并比较传入 &Endpoint 与 canonical Arc 内对象指针识别实际归属，随后在同一临界区加入 scope，避免换 endpoint 后迟到请求错误加入新域。不以设备公钥、UDP端口或地址作为 endpoint 实例身份。地址变化仍属于同一个 endpoint；替换 endpoint 创建新 scope。没有 canonical 归属的 one-shot 调用继续使用缓存线路，不增加未纳管的额外连接。

Wires 持有协调器，实际 scope 只弱持有 endpoint。每个 scope/peer 最多一条额外 Main，活动文件/请求持有 Arc，peer 只存 Weak，不保留空闲额外连接。两个文件重叠时复用，取消其中一个不能关闭另一个仍用的连接；最后 owner 释放关闭额外连接。文件请求和已有主连接的注册分开，额外连接不能替换主连接。

每个 peer 的异步准备锁限制同时一个建联；锁内外均复查活连接和策略。准备仍由当前 pull 持有，不派常驻任务。等待者保留自己的 caller 期限；一个 owner 过期不能广播为其他等待者的失败。取得连接额度仍未 dial 时就检查 caller/暂停/endpoint 归属，完成后再次检查，不让晚结果跨代发布。

## 有界资源与公平推进

首个候选参数：节点额外连接4、每peer额外连接1；bulk slice 每peer8、节点32；首内容独立节点8。4来自个人5设备含本机时最多4个对端的实验范围，8保留原文件窗口，32为4组窗口，首内容额度避免bulk耗尽后无有效内容；这些是待比较的候选值，不是用户批准的最优定值。

额外连接额度不足时不排队阻止文件；可选准备回到既有主连接，稍后别的文件可以再按当前资源情况尝试。准备锁等待与文件缓存读取并行。超过4个活跃对端仍须用实际5对端验证全部持续推进；不能因为只有4条额外连接就让第5个文件等待其他文件完成。

slice 先取得每peer额度，再取得节点额度，避免一个peer把大量等待请求灌入全局队列。首内容独立使用保留额度。使用公平的原生 semaphore；是否足够公平由多文件/多peer实际进度验证，不能只看permit数。客户端额度独立于已有服务端 encoded-response semaphore，避免双向传文件互相占住对方需要的额度。

permit 必须随请求及已完成但未提交的乱序结果一直持有，到顺序写入或取消丢弃才归还。只在RPC响应时归还会绕过内存上限。原每文件窗口8继续约束该文件；节点bulk32片与首内容8片合计至多约10MiB slice payload，不把请求对象、协议开销或QUIC缓冲冒称为这10MiB包含。

一次请求进入额度队列前确定原有效deadline，额度等待、实际请求及读重试共用它，不能等完额度再重新起算。提前取消、文件版本重启、ready结果丢弃都要归还额度，写请求不进入重放逻辑。

## 退役与锁

retire_peer、clear、let_go_served及endpoint替换必须撤回准备并关闭相应额外连接；主动退役及时释放逻辑连接额度，即使旧文件仍持有已关闭连接的Arc。旧owner Drop不能清除或关闭新scope/peer连接。无常驻扫描timer，清理在入队/准备/退役事件进行。

当前Wires retire_peer持有slots再served，let_go_served取走served后逐条关闭。pool模块不得反向取这些锁；协调器先取出需退役对象，释放自身map锁，再关闭连接/唤醒等待。endpoint归属查验的短临界区中不得await、dial或取异步锁。实现时写下实际锁顺序并检查所有调用点。

## 实现后必须验证

1. 两个真实并发文件共享唯一额外握手；各有首内容；取消一个后另一个完整精确完成，原Main身份保持。
2. 实际1/3/5对端，连接/准备峰值有界，超过额外额度者通过cached持续进展；所有文件在任一长文件完成前已有业务进展。
3. held head和真实乱序ready同时计入额度；每peer8、节点32不会因RPC已完成而失守；bulk饱和时其他peer首内容仍可推进。
4. caller过期/取消的owner与另一个未过期等待者分离，准备和两种额度无泄漏；未知endpoint不产生未纳管extra。
5. 同公钥两个真实endpoint不能共享额外连接；替换期间旧握手晚完成不能进入新scope或关闭新Main；地址变化不伪造新owner。
6. 本机/peer暂停、后台、policy变化和退役覆盖排队前后；应用/本机/CONNECTION_REFUSED拒绝仍终止，已闭20合同保持。
7. 最后文件结束无闲置extra；主动退役后额度立即可用，即使保留旧Arc；对侧真实close与cached Sessions作正控制。
8. 候选源码原标准组、适当Mac验证通过后，发行配置测首内容、吞吐与目录/终端长尾以及1/3/5设备CPU/字节/唤醒。性能协议、样本与门槛运行前另行固定，保留先前失败screen，不能要求Direct来抵消速度优先。
